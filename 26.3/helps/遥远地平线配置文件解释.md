# Distant Horizons 配置文件解释

- 对应文件：[`26.3/patch/config/DistantHorizons.toml`](../patch/config/DistantHorizons.toml)（容器内路径 `/app/config/DistantHorizons.toml`）
- 模组版本：Distant Horizons 3.3.4（`patch/mods/DistantHorizons-3.3.4-26.3-fabric-neoforge.jar`）
- 配置版本：`_version = 5`
- 文中引用的服务器侧背景值：`max-players = 8`、`view-distance = 16`、`simulation-distance = 10`（[server.properties](../patch/server.properties)）、JVM 默认 6G + ZGC（[init.sh](../init.sh)、[user_jvm_args.txt](../patch/user_jvm_args.txt)）

Distant Horizons（下称 DH）的作用是给原版渲染距离之外的地形做"低精度替身"（LOD）。在服务端跑 DH 时，**服务端会自己生成 LOD 数据**（不依赖原版把区块加载起来），玩家连上后由服务端把这份数据推给客户端。

所以服务端的 DH 开销只有三样：**CPU（生成）+ 磁盘（存储）+ 上行带宽（推送）**。下面三段参数，正好各管一样。

---

## 0. 三层结构：先分清哪一段有用

| 段           | 谁读它          | 管什么                                                           |
| ------------ | --------------- | ---------------------------------------------------------------- |
| `[server]`   | 仅服务端        | 生成/推送 LOD 数据的策略：距离、速率、带宽、"身份"               |
| `[common.*]` | 服务端 + 客户端 | LOD 数据本身的生成与存储方式（压缩、数据库、线程、世界生成器）   |
| `[client]`   | 客户端          | 渲染相关（视距、画质、雾效、调试）。**专用服务端进程不读这一段** |

---

## 1. `[server]`：往客户端推多少数据

### 1.1 距离类

| 参数                                   | 当前值 | 含义                                                                                         |
| -------------------------------------- | ------ | -------------------------------------------------------------------------------------------- |
| `realTimeUpdateDistanceRadiusInChunks` | `256`  | 别人挖/放方块、TNT、末影人搬砖等**实时变更**，要广播给半径 256 区块内的玩家                  |
| `maxGenerationRequestDistance`         | `4096` | 客户端最多能"点单"多远，让服务端现算 LOD（单位为格，4096 格 = 256 区块）                     |
| `maxSyncOnLoadRequestDistance`         | `4096` | 进服 / 走到新区域时，服务端最多主动同步多远的**已有** LOD。注释要求它 ≥ 上一条，此处两者相等 |

三个数字是同一个尺度：**256 区块 = 4096 格**。`realTimeUpdateDistanceRadiusInChunks = 256` 是整份文件里最贵的一项——半径线性增长，覆盖面积却是平方增长，256 区块半径差不多覆盖 26 万个区块。这个值本身是 DH 的默认值，不算配错，但它意味着"几乎整个世界里的动静都算你附近"。

### 1.2 速率类

| 参数                         | 当前值 | 含义                                                                 |
| ---------------------------- | ------ | -------------------------------------------------------------------- |
| `generationRequestRateLimit` | `20`   | 每个客户端每秒最多发 20 个生成请求；同时也是该玩家请求队列的长度上限 |
| `syncOnLoadRateLimit`        | `50`   | 每个客户端每秒 50 个同步请求；对应"刚进服疯狂下载"这条路径的限速     |

飞行中的玩家会不停请求新区域的 LOD，这两个值就是刹车。

### 1.3 带宽类（本仓库改动过）

| 参数                          | 当前值 | 换算                                                    |
| ----------------------------- | ------ | ------------------------------------------------------- |
| `globalBandwidthLimit`        | `4096` | 全服上传 4096 KB/s ≈ **4 MiB/s ≈ 33.6 Mbit/s**          |
| `playerBandwidthLimit`        | `512`  | 单人上传 512 KB/s ≈ **0.5 MiB/s ≈ 4.2 Mbit/s**          |
| `enableAdaptiveTransferSpeed` | `true` | DH 按客户端消费能力**自动调速**，尽量不把数据堆在连接里 |

注意 `max-players` 默认是 8，而 `8 × 512 = 4096`：单人和全服两个上限刚好咬合，即"每人最多 512，全员在线正好打满 4096，谁都挤不了谁"。所以真正要核对的不是这两个数字本身，而是**机器的上行带宽**——4 MiB/s 已经能吃满一条 30 Mbit/s 的家宽上传，而"简单的语音聊天"（24454/UDP）走的也是同一条线路。

`enableAdaptiveTransferSpeed = true` 是稳妥档：客户端吃不下时 DH 会自己降速，代价是速度快慢不可预测。设为 `false` 则速率固定，好处是行为可预测，坏处是客户端处理不过来时数据会在 TCP 缓冲里堆积，表现为玩家端卡顿甚至超时踢出。

### 1.4 开关

| 参数                    | 当前值 | 含义                                                                                                 |
| ----------------------- | ------ | ---------------------------------------------------------------------------------------------------- |
| `synchronizeOnLoad`     | `true` | 进服或进入新区域时，把服务端已有的 LOD 同步给客户端                                                  |
| `enableRealTimeUpdates` | `true` | 客户端渲染距离**之外**的区块，其方块变更也实时推给客户端（本服 view-distance=16，16 区块以外全靠它） |

### 1.5 身份类（不是性能项）

客户端要为每个服务器在本地建一个 LOD 数据文件夹，这一组参数决定"这次连的算不算同一个服务器"。

| 参数             | 当前值        | 含义                                                                                           |
| ---------------- | ------------- | ---------------------------------------------------------------------------------------------- |
| `serverKey`      | `""`          | 服务器没有固定 IP 时，用它强制复用同一个本地文件夹。留空则由客户端自己决定文件夹名             |
| `serverId`       | `-1418255052` | 自动生成的防碰撞 ID，避免两个独立服务器用同一个 `serverKey` 时互相覆盖 LOD。**不要手改**       |
| `levelKeyPrefix` | `""`          | 用代理（Velocity 等）挂多个后端时，每个后端填不同的值以区分                                    |
| `sendLevelKeys`  | `true`        | 服务端为每个世界发 level key，客户端据此认出"这是哪个世界的 LOD 库"。若用别的方式发 key 就关掉 |

### 1.6 在线修改

服务端参数可以用游戏内 `/dh config <键> [值]` 实时改，不必重启。

## 2. `[common.lodBuilding]`：LOD 数据怎么存在磁盘上

| 参数                         | 当前值           | 含义                                                                                                  |
| ---------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------- |
| `worldCompression`           | `VISUALLY_EQUAL` | 只记录**看得见**的方块/生物群系变化，矿脉这类被埋着的不记。数据库体积约为 `MERGE_SAME_BLOCKS` 的 0.7× |
| `databaseSyncMode`           | `NORMAL`         | LOD 数据库的 fsync 档位，见下表                                                                       |
| `dataCompression`            | `Z_STD_BLOCK`    | 用 zstd 压缩块数据：CPU 换磁盘体积                                                                    |
| `disableUnchangedChunkCheck` | `false`          | 名字是反的，见下                                                                                      |

`databaseSyncMode` 三档（需重启存档生效）：

| 档位     | 断电时的后果                       | 吞吐       | 磁盘占用 |
| -------- | ---------------------------------- | ---------- | -------- |
| `FULL`   | 数据永不丢失/损坏（ACID）          | ~2k 写/秒  | ~70%     |
| `NORMAL` | 最近的写入可能丢，但数据库不会损坏 | ~14k 写/秒 | ~40%     |
| `OFF`    | 数据库可能损坏                     | ~16k 写/秒 | ~6%      |

注释里补了两句关键限定：**"意外进程退出对三个档位都是安全的"，只有真断电才是风险**；而且 LOD 数据丢了是可以重算的。所以 `NORMAL` 通常是正确选择。

`worldCompression` 的代价：被藏起来的方块没进库，将来挖开暴露时可能看到空洞或错色，直到该区块重新生成。配置里 `ignoredRenderBlockCsv` 的注释也提到"出现空洞就切回 `MERGE_SAME_BLOCKS` 并重新生成 LOD"。

`disableUnchangedChunkCheck = false` 表示**保留**"内容没变的区块跳过重建"这个优化。若设为 `true`，等于关掉检查、每次都重算：更费 CPU 和磁盘写，但不会漏掉更新。

## 3. `[common.multiThreading]`：CPU 怎么分

| 参数                 | 当前值  | 含义                                                         |
| -------------------- | ------- | ------------------------------------------------------------ |
| `numberOfThreads`    | `4`     | DH 自己的 LOD 生成线程数。这是"CPU 换出图速度"               |
| `threadRunTimeRatio` | `"1.0"` | 每个线程的占空比，`1.0` = 全速不歇；调低可让线程跑一阵歇一阵 |
| `threadPriority`     | `5`     | Java 线程优先级，只有和 C2ME 互相饿死时才需要动              |

本服 JVM 用 ZGC（[user_jvm_args.txt](../patch/user_jvm_args.txt)），ZGC 自己还有一批并发线程；`numberOfThreads = 4` 是不去抢主线程与 GC 的保守值。想出图更快就往上加，但要留头给 GC 和 server tick。**想降 CPU 占用时，`threadRunTimeRatio` 比 `numberOfThreads` 更精细**：线程数不好减的时候调它即可。

## 4. `[common.worldGenerator]`：远处没人去过的地形怎么"造"出来

这段决定 DH 那些**玩家从没加载过**的区块的 LOD 长什么样。对服务端来说，这批数据正是要发给客户端的东西，所以它直接决定"远处看起来对不对"。

| 参数                             | 当前值                | 含义                                                                                                                               |
| -------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `chunkGeneratorMode`             | `FEATURES`            | 生成到什么程度，见下                                                                                                               |
| `generatorPlan`                  | `SURFACE_THEN_CHUNKS` | 先粗糙表面、后补细节，速度与准确度的折中                                                                                           |
| `surfaceRegenMaxDistancePercent` | `"-1.0"`              | 只对 `SURFACE_THEN_CHUNKS` 有效，控制第二遍高质量生成铺到多远（相对渲染距离的百分比，-1 = 无限制）。注释明说**专用服务器上无作用** |
| `limitIfServerUnhealthy`         | `true`                | 服务端 tick 太慢时暂停 DH 生成（保 tick 的护栏，建议保留）                                                                         |
| `pauseIfMovingQuickly`           | `true`                | 玩家/视角快速移动时暂停生成，优先保证加载                                                                                          |
| `generationMaxChunkRadius`       | `0`                   | 生成范围上限，`0` = 不限制                                                                                                         |
| `generationCenterChunkX` / `Z`   | `0`                   | 上面那个半径的中心点                                                                                                               |
| `showGenerationProgress`         | `"DISABLED"`          | 生成进度显示位置（`OVERLAY` / `CHAT` / `LOG` / `DISABLED`）                                                                        |

`chunkGeneratorMode` 三档：

| 档位                | 行为                                                       | 代价                                                          |
| ------------------- | ---------------------------------------------------------- | ------------------------------------------------------------- |
| `PRE_EXISTING_ONLY` | 只给已经生成过的区块做 LOD                                 | 最省，远处什么都没有                                          |
| `FEATURES`          | 用世界生成器算地形，但**不含结构**（村庄、地牢等不会出现） | 注释警告"和某些世界生成模组一起可能造成世界生成 bug 或不稳定" |
| `INTERNAL_SERVER`   | 让本地服务端真的加载/生成每个区块，最兼容、结构正确        | 会卡服务端；**且会真的写进原版 region 文件**                  |

> ⚠️ 本仓库装了 Terralith、Tectonic、lithostitched、Structory、Villages Revamped、dungeons-and-taverns 等世界生成/结构类模组，正好命中 `FEATURES` 的那条警告。建议实测验证：飞到没人去过的地方，看远处地形与结构是否正确。

`generatorPlan` 四档：`SURFACE_THEN_CHUNKS`（推荐，折中）／`SURFACE_ONLY`（更快更省内存，但没树没村庄）／`CHUNKS_ONLY`（更准更慢，自定义世界推荐）／`DISABLED`（不生成远处地形）。

## 5. `[client]`：服务端不读

里面的 `lodChunkRenderDistanceRadius`、`maxHorizontalResolution`、雾效、调试开关等全是客户端侧的东西，专用服务端进程不会用到。DH 确实存在某种服务端→客户端的配置下发机制（本文件里 `logConnectionConfigChangesToFile` 的描述就是"服务端发来的配置变更会被记录"），但**以每个玩家自己的 `DistantHorizons.toml` 为准**，不要靠这一段去遥控客户端。

---

## 6. 本仓库显式改动过的 4 处（带 `# CHANGED` 注释）

| 参数                          | 值     | 说明                                                           |
| ----------------------------- | ------ | -------------------------------------------------------------- |
| `globalBandwidthLimit`        | `4096` | 全服上传 4 MiB/s，与 `max-players × playerBandwidthLimit` 咬合 |
| `playerBandwidthLimit`        | `512`  | 单人上传 0.5 MiB/s                                             |
| `enableAdaptiveTransferSpeed` | `true` | 开着自动调速，避免把数据堆在连接里                             |
| `numberOfThreads`             | `4`    | DH 生成线程数（1.21.1 那份是 2）                               |

其余未标注的值均为 DH 生成的默认值。顺带说明：1.21.1 那份配置里同样是 `4096` / `512` 却没有标记，说明这套 `# CHANGED` 标记是后来才加的约定，不宜当作严格的事实来源。

## 7. 按症状查表

| 症状                          | 先动这几项                                                                                                |
| ----------------------------- | --------------------------------------------------------------------------------------------------------- |
| 玩家连上后卡顿 / 被踢超时     | `enableAdaptiveTransferSpeed`、`playerBandwidthLimit`、`globalBandwidthLimit`                             |
| 服务端 CPU 高、tick 掉        | `numberOfThreads`、`threadRunTimeRatio`、`realTimeUpdateDistanceRadiusInChunks`、`limitIfServerUnhealthy` |
| 进服后半天才看到远方          | `syncOnLoadRateLimit`、`playerBandwidthLimit`                                                             |
| 远处地形不对 / 没有村庄与树木 | `chunkGeneratorMode`、`generatorPlan`（以及 `worldCompression` 造成的空洞）                               |
| 磁盘占用爆炸                  | `worldCompression`、`databaseSyncMode`、`dataCompression`                                                 |
| 远处出现空洞                  | `worldCompression` 改为 `MERGE_SAME_BLOCKS` 后重新生成 LOD                                                |

## 8. 与 1.21.1 配置的差异（仅列出）

对比对象：`1.21.1/patch/config/DistantHorizons.toml`（`_version = 4`）与新配置（`_version = 5`）。大部分差异来自模组本身升级（DH 2.x → 3.3.4）而非人为改动。

### 8.1 同名参数、值不同

| 参数                          | 1.21.1      | 26.3          | 备注                                  |
| ----------------------------- | ----------- | ------------- | ------------------------------------- |
| `_version`                    | `4`         | `5`           | 配置架构版本                          |
| `serverId`                    | `864061729` | `-1418255052` | 自动生成，随机                        |
| `numberOfThreads`             | `2`         | `4`           | 本仓库人为调整                        |
| `enableAdaptiveTransferSpeed` | `true`      | `true`        | 值相同，但 26.3 加了 `# CHANGED` 标记 |
| `globalBandwidthLimit`        | `4096`      | `4096`        | 值相同，但 26.3 加了 `# CHANGED` 标记 |
| `playerBandwidthLimit`        | `512`       | `512`         | 值相同，但 26.3 加了 `# CHANGED` 标记 |

也就是说 `[server]` 段里真正改动的只有 `numberOfThreads`，带宽那一组只是补上了标记。其余 `[server]` 值（256 / 4096 / 4096 / 20 / 50 / true / true）两版完全一致。

### 8.2 26.3 新增的配置项

| 段                                            | 新增项                                                                                                                                                                                        |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[server]`                                    | 无                                                                                                                                                                                            |
| `[common.lodBuilding]`                        | `databaseSyncMode`、`dataCompression`                                                                                                                                                         |
| `[common.logging.warning]`                    | `showExplicitGcDisabledWarning`、`logExplicitGcDisabledWarning`                                                                                                                               |
| `[common.worldGenerator]`                     | `chunkGeneratorMode`（由 `distantGeneratorMode` 改名而来）、`generatorPlan`、`surfaceRegenMaxDistancePercent`、`limitIfServerUnhealthy`、`pauseIfMovingQuickly`                               |
| `[client.advanced.graphics]`                  | `enableAntiAliasing`                                                                                                                                                                          |
| `[client.advanced.graphics.texture]`          | 整个新段：`blocksDontUseSideTextureCsv`、`maxTexturedLodDetailLevel`、`enableTexturedLods`、`blocksDontRenderTextureCsv`、`blockTagsDontUseSideTextureCsv`、`blocksAlwaysRasterizeTextureCsv` |
| `[client.advanced.graphics.quality]`          | `useCameraPositionForQualityDropOff`、`maxZoomQualityIncrease`、`increaseQualityWhenZoomedIn`                                                                                                 |
| `[client.advanced.graphics.genericRendering]` | `enableMultiLayerClouds`                                                                                                                                                                      |
| `[client.advanced.graphics.culling]`          | `blocksToIgnore`、`tintWithAvoidedBlocks`（从 `quality` 段挪过来）                                                                                                                            |

### 8.3 26.3 移除的配置项

| 段                                   | 移除项                                       | 说明                                               |
| ------------------------------------ | -------------------------------------------- | -------------------------------------------------- |
| `[server]`                           | `enableServerGeneration`                     | 新版本中该功能不再由这个开关控制                   |
| `[server.experimental]`              | 整段（`enableNSizedGeneration`）             | 新版的对应功能改在别处                             |
| `[common.lodBuilding.experimental]`  | 整段（`upsampleLowerDetailLodsToFillHoles`） | —                                                  |
| `[common.worldGenerator]`            | `enableDistantGeneration`                    | 功能由 `chunkGeneratorMode` / `generatorPlan` 接管 |
| `[client.advanced.graphics.quality]` | `dhFadeFarClipPlane`                         | —                                                  |

### 8.4 改名 / 挪位

| 1.21.1                                                                       | 26.3                                                      |
| ---------------------------------------------------------------------------- | --------------------------------------------------------- |
| `[common.worldGenerator] distantGeneratorMode`                               | `[common.worldGenerator] chunkGeneratorMode`              |
